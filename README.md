# influencer-skill

Claude Code skills that turn a creator's brand profile + a topic into on-brand,
researched content (video scripts, captions/hashtags, or an article) for every
network the creator uses. Built to also be installable/publishable via
[skills.sh](https://skills.sh).

## How it works

Two skills, used in order:

1. **`brand-setup`** — one-time (or occasional) interview that captures the creator's
   brand, tone, main/secondary networks, inspirations, and desired content structure.
   Writes six Markdown files at the project root.
2. **`content-creator`** — given a topic, researches it, then generates one HTML page
   per configured network (video script + caption/hashtags for video networks, or an
   article body for `article`), and keeps a root `index.html` of everything produced.

## Usage

```
"configure my brand"          → runs brand-setup
"create content about <topic>" → runs content-creator
"change the hook on the YouTube script for topic 001" → content-creator's revision flow
```

Run `brand-setup` first — `content-creator` refuses to run until the brand files exist.
Re-running `brand-setup` later only asks about what's missing or what you explicitly
want to change; it won't repeat the full interview.

## Project structure

```
influencer-skill/
├─ skills/                        # canonical source of both skills — edit files here
│  ├─ brand-setup/
│  │  ├─ SKILL.md                 # interview procedure
│  │  └─ templates/                # blank templates for the 6 root config files
│  └─ content-creator/
│     ├─ SKILL.md                 # research + generation + revision procedure
│     └─ templates/                # HTML/Tailwind page + index skeletons
│
├─ .claude/skills/
│  ├─ brand-setup      -> ../../skills/brand-setup       # symlink, do not edit here
│  └─ content-creator  -> ../../skills/content-creator   # symlink, do not edit here
│
├─ skills.sh.json                 # groups the skills on the skills.sh marketplace page
├─ .gitignore                     # keeps generated/personal files out of git
│
├─ BRANDING.md                    # created by brand-setup: name, what they do, audience
├─ COMMUNICATION_STYLE.md         # created by brand-setup: tone of voice
├─ MAIN_INFLUENCE_ZONE.md         # created by brand-setup: the one primary network
├─ SECONDARY_INFLUENCE_ZONE.md    # created by brand-setup: zero or more secondary networks
├─ INSPIRATIONS.md                # created by brand-setup: reference creators/brands
├─ STRUCTURES.md                  # created by brand-setup: content structure per network
├─ index.html                     # created/updated by content-creator: index of all topics
│
└─ content/
   └─ <NNN>-<topic-slug>/         # one folder per topic, NNN = 001, 002, ...
      ├─ RESEARCH_SOURCE.md       # sources found for the topic
      ├─ RESEARCH.md              # synthesized research
      └─ pages/
         ├─ youtube.html          # one file per configured network
         ├─ instagram.html
         └─ ...
```

`skills/` is the single source of truth for both skills — `.claude/skills/brand-setup`
and `.claude/skills/content-creator` are **symlinks** into it (the same mechanism the
`npx skills` CLI itself uses), so Claude Code resolves them transparently. Never edit
the files through the `.claude/skills/` path directly; always edit under `skills/`.

Everything from `BRANDING.md` down is generated by actually *using* the skills and is
listed in `.gitignore` — it holds a real creator's brand and content, so it must never
end up in a public copy of this repo.

Valid network slugs (used both in the config files and as filenames): `article`,
`youtube`, `instagram`, `tiktok`.

## Publishing to skills.sh

skills.sh doesn't have a submission form or approval queue — it indexes public git
repositories directly. A skill starts showing up on the leaderboard/search automatically,
via anonymous telemetry, the first time someone runs `npx skills add <owner>/<repo>`
against your repo. So "publishing" just means:

1. **Make this repo public** (GitHub, GitLab, or any git host). The `skills/` top-level
   folder is exactly the portable layout the `skills` CLI expects, so no repackaging is
   needed.
2. **Double-check `.gitignore` did its job** before pushing — run `git status --ignored`
   and confirm `BRANDING.md`, `content/`, `index.html`, etc. show up as *ignored*, not
   as untracked files waiting to be added. Never commit those.
3. **Push it**, then sanity-check discovery from anywhere:
   ```bash
   npx skills add <owner>/<repo> --list
   ```
   This should list `brand-setup` and `content-creator` without installing anything.
4. Optionally tweak `skills.sh.json` to change how the two skills are grouped/labeled
   on the marketplace page — it's cosmetic only, not required for indexing.
5. From here on, every `npx skills add <owner>/<repo>` (by you or anyone else) is what
   feeds the skills.sh leaderboard — there's nothing further to do on your side.

## Design notes

- Each network's page is generated by its own subagent, in parallel, and is fully
  self-contained (Tailwind via CDN, no build step). That's what makes later revisions
  cheap: editing one network's page never requires reloading research or the other
  networks' content.
- `index.html` is never rebuilt from scratch — each `content-creator` run reads it,
  updates only the current topic's section, and leaves the rest untouched.
